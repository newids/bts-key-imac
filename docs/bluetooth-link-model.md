# 블루투스 연결과 앱의 역할

iMac과 MacBook 사이의 블루투스 연결이 어떤 층으로 이루어지고, 각 층을 누가 만들고 누가 끊는지, 앱이 어디까지 관여하는지 정리한다. 근거는 `docs/connection-audit.md`(1~7차 감사)와 Bluetooth HID Profile 1.1.1이다.

## 1. 역할

| 기기 | HID 역할 | 하는 일 |
|---|---|---|
| iMac | 호스트 | 키보드를 찾고, 페어링을 시작하고, 입력을 받는다 |
| MacBook (이 앱) | 기기(키보드·마우스) | 검색에 응답하고, 서비스를 게시하고, 입력을 보낸다 |

규격이 정한 동작(HID 1.1.1 표 5.2):

| 동작 | 호스트 | 기기 |
|---|---|---|
| 검색(Inquiry) | 필수 | 선택 |
| 검색 응답(Inquiry scan) | 사용 안 함 | 필수 |
| 호출(Paging) | 필수 | 재연결을 선언한 경우 필수 |

따라서 **MacBook은 주변 기기를 검색하지 않는다.** MacBook은 검색 가능한 상태가 되어 iMac이 찾게 한다. macOS에서 Mac이 검색 가능해지는 것은 시스템 설정의 Bluetooth 화면이 열려 있는 동안뿐이다.

## 2. 연결의 네 층

아래에서 위로 쌓인다. 위층은 아래층이 있어야 존재한다.

| 층 | 무엇인가 | 누가 만드나 | 시스템 설정 표시 | 앱 표시 |
|---|---|---|---|---|
| ① 페어링 | 두 기기가 링크 키를 나눠 가진 상태. 전원을 꺼도 남는다 | 사람 (iMac에서 시작) | 목록에 기기가 보임 | `페어링됨 · 링크 없음` |
| ② 블루투스 링크 | 두 기기 사이의 무선 연결(ACL) | 한쪽이 상대를 호출 | **"연결됨"** | `링크 연결됨 · 키보드 채널 없음` |
| ③ HID 채널 | 제어(0x11)·인터럽트(0x13) 채널 | 앱 | 변화 없음 | `연결됨 · 입력: MacBook` |
| ④ 입력 전달 | 키·포인터 입력이 iMac으로 감 | 사람 (⌥⌘K) | 변화 없음 | `연결됨 · 입력: iMac` |

**시스템 설정의 "연결됨"은 ②층만 뜻한다.** 키보드로 쓸 수 있는 것은 ③층부터다. 그래서 양쪽 설정에는 "연결됨"인데 앱은 연결이 안 된 상태가 있을 수 있다. 앱은 이 상태를 메뉴 상태 줄에 따로 표시한다.

②층만 있고 ③층이 없으면 링크는 약 15초 뒤 스스로 끊긴다. 앱은 연결에 실패하면 ②층을 바로 해제해 "연결됨"이 남지 않게 한다.

## 3. 앱이 하는 일과 하지 않는 일

| 앱이 한다 | 앱이 하지 않는다 |
|---|---|
| HID 서비스를 앱 수명에 한 번 게시 | 주변 기기 검색 |
| 대상 iMac을 호출해 ②층을 만들고 ③층을 연다 | 페어링 시작·삭제 |
| 실패 뒤 ②층 해제 | 대상이 아닌 기기 호출 (이름 조회 포함) |
| 끊김 뒤 한 번 재시도 | 두 번 이상 자동 재시도 |
| 페어링 목록을 5초마다 확인해 새 iMac 감지 | 앱 프로세스 안에서 페어링 목록 조회 |

## 4. 연결 순서

앱은 항상 자기 쪽에서 연결을 연다.

```
0.0초  대상 iMac 호출
~2초   ②층 연결 완료
       1.5초 대기
~3.5초 채널 0x11 요청 → 암호화 → 열림
       채널 0x13 요청 → 열림
~4초   ③층 완료. iMac의 초기 요청(프로토콜 설정, LED 상태)에 응답
```

지켜야 하는 세 가지. 모두 실측으로 확인한 것이다.

1. **②층 완료 뒤 1.5초를 기다린 다음 채널을 연다.** 바로 열면 암호화 시작 요청에 iMac이 응답하지 않아 5.5초 뒤 링크가 끊긴다(상태 708). 기다린 뒤에는 암호화가 대개 23ms에 끝난다. 그래도 17회 중 1회는 같은 시간 초과가 났고, 그때는 자동 재시도가 회복했다.
2. **앱 프로세스에서 `IOBluetoothDevice.pairedDevices()`를 호출하지 않는다.** 한 번이라도 호출하면 그 프로세스의 이후 채널 열기가 모두 실패한다(오류 -536870212, 3초 뒤 메인 스레드 멈춤). 이 호출은 양쪽 전송 방식으로 페어링된 Mac을 두 개의 객체로 돌려준다. 목록은 보조 프로세스(`BTSKey --list-paired`)가 읽는다.
3. **연결 알림·채널 개방 알림을 등록하지 않는다.** 등록하면 기기 객체가 연결되지 않은 상태로 고정된다(6차 감사).

iMac이 직접 여는 채널은 받지 못한다. 채널은 앱 프로세스까지 도착하지만 macOS 프레임워크가 앱에 알림과 데이터를 넘기지 않는다(7차 감사 E1~E3, E5). iMac이 올린 링크는 연결돼 있는 동안 앱에 보이지 않는다. 연결 알림도 오지 않고 연결 상태 값도 바뀌지 않는다. 보이는 것은 그 링크가 끊어질 때의 끊김 알림뿐이며, 앱은 그때 자기 쪽에서 연결한다.

## 5. 끊김과 재연결

| 상황 | 판별 | 앱의 동작 | 근거 |
|---|---|---|---|
| iMac이 "연결 해제"를 누름 | 채널이 닫혔는데 ②층은 살아 있음 | 재시도 없이 대기 | HID §5.3.4.6: 호스트가 끊으면 바로 재연결하지 않는다 |
| 링크가 끊김 (거리, 잠자기) | ②층이 먼저 사라짐 | 4초 뒤 한 번 재시도, 실패하면 대기 | HID §5.1.5: 재연결은 멈춰도 되고 그 뒤는 사용자 조작 |
| iMac이 링크를 올림 (깨어남, "연결" 클릭) | 앱이 쓰지 않은 링크의 끊김 알림 (iMac의 시도 후 16~19초) | 1초 뒤 한 번 연결. 시도부터 약 25초 | 같은 신호로는 다시 연결하지 않는다 |
| 사용자가 앱에서 "연결 해제" | — | 모든 자동 동작 중지 | |
| MacBook이 잠에서 깸 | — | 한 번 연결 | |

대기 상태에서 다시 연결하는 방법은 메뉴의 **지금 다시 연결**이다. 연결에 성공하거나 사용자가 직접 연결을 누르면 자동 시도 횟수가 처음으로 돌아간다.

자동 시도를 줄인 이유: 호출은 MacBook의 무선을 몇 초씩 점유한다. 되풀이되면 MacBook에 연결된 다른 블루투스 기기(키보드, 트랙패드, 이어폰)가 끊기거나 늦어진다.

## 6. 새 iMac인지 이전 iMac인지 판별

앱은 페어링 목록과 두 가지 기록을 대조한다.

- **페어링 기록**: 각 페어링을 앱이 처음 본 시각. 디스크에 저장되므로 앱이 꺼져 있던 동안의 페어링도 다음 실행 때 "새로 생긴 것"으로 잡힌다.
- **연결 기록**: 각 iMac에 마지막으로 키보드로 연결된 시각.

| 분류 | 조건 | 메뉴 표시 | 앱의 동작 |
|---|---|---|---|
| 새 기기 | 앱이 지켜보는 동안 페어링됨, 연결한 적 없음 | 새 기기 · 아직 연결한 적 없음 | 대상으로 삼고 연결 |
| 이전 기기 | 현재 페어링으로 연결한 적 있음 | 마지막 연결 ○분 전 | 앱 시작 시 마지막 대상이면 연결 |
| 다시 페어링됨 | 연결한 적 있고, 그 뒤 다시 페어링됨 | 다시 페어링됨 | 새 기기와 같음 |
| 연결한 적 없음 | 기록 시작 전부터 페어링돼 있었음 | 아직 연결한 적 없음 | 사용자가 고를 때만 |
| 페어링 해제됨 | 목록에서 사라짐 | 페어링 해제됨 | 재시도 중지, 대상에서 제거 |

판별에서 지키는 것:

- iMac이 페어링을 시작하면 MacBook에는 iMac의 기기 종류가 기록되지 않는다(값 0). 종류가 없는 기기는 페어링 기록으로 판단한다. 앱이 지켜보는 동안 새로 생긴 것이면 호스트 후보, 처음부터 있던 것이면 사용자의 다른 기기(iPhone, iPad, Watch)로 본다.
- 페어링이 목록에서 한 번 빠진 것만으로는 삭제로 보지 않는다. 두 번 연속 빠져야 삭제다. 블루투스 데몬이 바쁠 때 목록이 일부만 올 수 있기 때문이다.
- 한 번에 두 대 이상이 새로 페어링되면 고르지 않고 사용자에게 맡긴다.
- 앱 시작 시에는 첫 목록을 확인한 뒤에 연결한다. 새 iMac이 있으면 이전 iMac을 호출하지 않는다.

## 7. 새 iMac으로 옮기는 절차

| 순서 | 사람 | 프로그램 |
|---|---|---|
| 1 | MacBook의 시스템 설정 → Bluetooth 화면을 열어 둔다 | (macOS가 MacBook을 검색 가능 상태로 둔다) |
| 2 | 새 iMac의 Bluetooth 설정에서 MacBook 옆 "연결"을 누르고 양쪽에서 승인한다 | |
| 3 | | 5초 안에 새 페어링 감지, 새 기기로 분류 |
| 4 | | HUD "새 iMac 페어링됨", 이어서 "연결 중" |
| 5 | | 링크 → 1.5초 대기 → 채널 0x11 → 0x13 |
| 6 | HUD "연결됨" 확인 | |
| 7 | ⌥⌘K로 입력 전환 | 입력 전달 |

이전 iMac과의 페어링은 지우지 않아도 된다. 앱은 대상이 아닌 iMac을 호출하지 않는다.
